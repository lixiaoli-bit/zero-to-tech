构建工具 · Vite 从零上手 工程化

4.1 遗留问题 · 为什么需要构建工具

三大难受
  • 想看一眼效果太麻烦 —— 模块化之后本地打不开，ES 模块必须走服务器
  • 打开页面十几条请求，光 CSS 就 8 个文件
  • 改了 CSS 刷新没变，浏览器缓存坑人

有一类工具专门收拾这些——构建工具，最流行的叫 Vite（作者尤雨溪）。

先装 Node.js · 让 JS 跑在电脑上

Vite 是用 JavaScript 写的命令行工具，需要 Node.js 环境。类比：跑 .py 要装 Python，开 .xlsx 要装 Excel。

node -v # 看到 v20.x.x 之类
npm -v # 看到 10.x.x 之类

npm 随 Node 一起安装，apt 给整台电脑装，npm 默认给“当前这一个项目”装。

初始化项目 · npm init =这个项目我要来管

进入项目根目录（与 index.html 同级），运行：

npm init -y

生成 package.json —— 项目的“npm 档案”。可以手动精简，只留 name 和 version：

{ "name": "zero-to-tech", "version": "1.0.0" }

安装 Vite

npm install -D vite
  • node_modules/ 出现
  • package.json 多了 devDependencies -D的作用就是只是工具，不打包上线
  • package-lock.json 锁定版本
node_modules/vite/ 代码本体
node_modules/.bin/vite 可执行命令

三条核心命令：dev · build · preview

dev：随改随看

./node_modules/.bin/vite

Vite 起本地服务器 localhost:5173，热更新，难受1 解决。

build：打包上线版本

./node_modules/.bin/vite build

产出 dist/：

  • 8 个 CSS → 1 个（带 hash）
  • 几个 JS 模块 → 1 个（带 hash）

难受2（请求太多）和 难受3（缓存坑）一并解决。

preview：上线前本地预览一下 dist

./node_modules/.bin/vite preview

这条命令就是起服务器专门伺服 dist，上线前自测。

源代码 ≠ 运行的代码
你维护的是 js/,css/ 源码，线上跑的是 dist/。永远改源码，然后 build，不要手动改dist, dist才是真正上线的。

用 npm run 告别长命令

在 package.json 的 scripts 中登记别名：

"scripts": {
"dev": "vite",
"build": "vite build",
"preview": "vite preview"
}

npm run xxx 即执行 scripts 中的 xxx 命令，它会在 node_modules/.bin 里自动查找（如 vite），无需写路径。

apt 只管软件装卸，npm 不只是包管理器，还依据 package.json 充当项目命令的执行者。npm run dev 实际运行的是你自定义的 vite 命令，npm 只是照单执行。核心：命令是你的，npm 只是代劳。

命令作用何时使用
npm run dev起本地服务器，热更新开发时全程
npm run build打包成 dist/上线前生成
npm run preview本地预览 dist上线前自测

在根目录新建.gitignore：忽略可重建的产物

node_modules/
dist/

它们都可以通过 npm install 和 npm run build 重新生成，不必提交 Git。

用 npm 管理依赖 · 告别 CDN

之前 cards.js 里直接从 CDN 引 anime：

import { animate, stagger } from "cdn.jsdelivr.net/...";

现在装到本地：

npm install animejs

回到card.js,score.js 然后修改 import：

import { animate, stagger } from "animejs";

Vite 会自动映射到 node_modules，不再依赖外网，版本锁在手里。

改完，再 npm run build 一次，此时 dist 里那个 js 已经不一样了——anime.js 也被打了进去

这节课你该理解什么

  • 构建工具（Vite）解决开发体验问题：本地服务器、合并文件、加 hash
  • Node.js 是 JS 运行环境，npm 是“按项目管理”的应用商店
  • package.json 是项目档案，scripts 是命令别名表
  • 源码（你改）≠ 运行代码（dist），node_modules 和 dist 可重建，不提交 写进.gitignore
  • dependencies（运行时库）vs devDependencies（开发工具）
留个尾巴：复用还没解决 —— 两个 HTML 页面共用导航，却各自写了一遍。下一节 React 将把多页面合成单页，组件复用，导航写一次处处可用。
