Next.js · 框架代价 · 预渲染 从 React 到生产级

第一部分 · 框架的代价

React 是一套规则，借助 Vite 翻译成 html/css/js。但最终浏览器拿到的是空壳 index.html + JS 包，页面是 JS 现画的。

三个问题，同一个病根：404、白屏、SEO 差 —— 都是因为页面不是真实文件，而是浏览器临时算出来的。

根治方案：提前把每一页“画好”，存成真实 HTML 文件。Next.js 就是替我们做这件事的框架。

Next.js 是什么

Next.js 是 React 之上的生产级框架。React 管组件，Next 管“组件之外、与整个 web 应用相关、上线必须的事”：路由、SEO、首屏快。

二者不是二选一，而是叠加。Next 真正解决两件事：
路由 —— 哪个网址显示哪一页，告别手搓判断；
预渲染 —— 把页面渲染成真实 HTML，一次解决 404/白屏/SEO。

Next 自带构建工具，不再用 Vite。但 dev / build 概念不变，只是执行者换了。

cd zero-to-tech-4-5
npm install
npm run dev

第二部分 · 文件夹即路由

zero-to-tech-4-5/
app/ ← Next.js 的“页面区”
   layout.jsx ← 全站外壳
   page.jsx ← / 这一页
   text-lab/
     page.jsx ← /text-lab 这一页
components/ (Nav, HomeView, TextLabView, AnimatedCardGrid...)
data/ (site.js 一字未改)

文件夹 = 路由：app/page.jsx → / ，app/text-lab/page.jsx → /text-lab。不用注册路由表，新建页面只需创建对应文件夹。

app/text-lab/page.jsx (仅5行)
import TextLabView from "../../components/TextLabView.jsx";
export default function Page() { return <TextLabView />; }

它的全部工作就是说“/text-lab 这个 URL 渲染 TextLabView 这个组件”，监听 URL、刷新不丢、前进后退 —— Next 全包了。

第三部分 · use client 开关

组件文件顶上的 "use client" 决定渲染位置：

  • 默认（无 "use client"）：服务端组件，在 build 时渲染成 HTML，首屏快、SEO 友好。
  • 有 "use client"：客户端组件，带交互/动画（useState、useEffect、usePathname 等），会额外发送 JS 到浏览器。
有 "use client"
Nav.jsx, InputCard.jsx, ResultCard.jsx, AnimatedCardGrid.jsx
(导航高亮、打字计数、动画)
无 "use client"
HomeView.jsx, TextLabView.jsx, PageHeading.jsx, page.jsx
(纯展示，无交互)

构建：npm run build

npm run build

输出末尾显示 ○ (Static) prerendered as static content，且 .next/server/app/ 下出现真实的 index.html 和 text-lab.html。

现在 /text-lab 有了真实文件，404 病根解除。首屏快、SEO 收录，都是同一件事。

注意：.next/server/app/ 产物与 Vite 的 dist/ 不同，不能直接丢给 Nginx 静态部署，下一节讲。

第四部分 · 迁移 & 从零新建

把已有项目搬成 Next

  • 删除 ~/zero-to-tech 下所有文件（保留 .git）
  • 把 zero-to-tech-4-5/ 全部拷入
  • npm install && npm run dev

保留 .git 是为了连接 GitHub 和提交历史。最后 git add / commit / push。

从 0 新建 Next 项目

npm create next-app@latest

核心概念回顾

  • 文件夹 = 路由：app/text-lab/page.jsx → /text-lab，无需配置。
  • 跳转交给框架：<Link href="..."> 接管路由，App.jsx + useRoute.js 消失。
  • 预渲染成真实 HTML：npm run build 输出真实文件，首屏快、SEO 友好。
