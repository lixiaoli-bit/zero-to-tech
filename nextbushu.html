Next.js · 静态导出 · 部署笔记 output: "export"

两条路：A 常驻服务 vs B 静态导出

路 A：next start
Node 常驻服务，按请求动态渲染，适合数据频繁变化的站点。代价：一直跑着的程序，更重。
路 B：output: "export"
静态导出 out/，纯 HTML + JS，Nginx 直接 serve。轻量、快速，但内容 build 时固定。
怎么选？ 展示站、博客、文档、静态前端 + 后端 API → 走 B。 需要每个请求动态调整内容 → 走 A。

差别一：加一行 output: "export"

在 next.config.mjs 中配置，告诉 Next 导出静态文件。

// next.config.mjs
const nextConfig = {
  output: "export", // ← 就加这一行
};
export default nextConfig;

执行 npm run build 后，项目根目录生成 out/ 文件夹：

out/
├── index.html
├── text-lab.html ← 真实存在的页面
├── 404.html
└── _next/static/ ← CSS / JS

记得把 out/ 和 .next/ 加入 .gitignore。

差别二：Nginx 指向 out/ + try_files

部署命令与之前几乎一样，但 Nginx 配置需要调整：

# 本地推代码
git push

# 服务器拉取 + build
ssh ubuntu@你的服务器IP
cd ~/zero-to-tech
git pull
npm install
npm run build # 服务器上也生成 out/

但是要修改 Nginx 配置

sudo vim /etc/nginx/sites-enabled/default
server {
  listen 80 default_server;
  server_name _;
  root /home/ubuntu/zero-to-tech/out; # ← 指向 out/，原来这里是dist
  index index.html;
  location / {
    try_files $uri $uri.html $uri/ =404; # ← 自动补 .html，
  }
}

检查并重载：

sudo nginx -t
sudo systemctl reload nginx
try_files 的作用
当访问 /text-lab 时，Nginx 先找 text-lab 文件，找不到就自动补 .html 再找 —— 而 out/text-lab.html 真实存在，所以不再 404。
