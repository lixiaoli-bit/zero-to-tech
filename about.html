Git · 服务器 · 部署笔记 从零到公网

Git 本地仓库

仓库 (repository) 是 Git 管理的目录，电脑里可以有很多个。

第 1 步：确认 Git 已安装

git --version

第 2 步：配置提交身份（每台电脑一次）

先检查是否已配置：

git config --global user.name
git config --global user.email

如果未配置，执行：

git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

第 3 步：初始化仓库

进入项目目录并初始化：

cd ~/zero-to-tech
git init # 让git管这个目录

然后查看状态：

git status

建议做一个小改动，然后走一遍 add / commit：

git add .
git commit -m "修改首页标题文案"

GitHub 远程仓库

第 1 步：在 GitHub 创建空仓库

  • 仓库名：zero-to-tech
  • Public / Private：按需求
  • 不勾选 Initialize this repository with a README

第 2 步：配置 SSH（每台电脑一次）

生成密钥对：仅仅数字

ssh-keygen -t ed25519 -C "你的邮箱"
# 连续回车默认值
生成后一般会有：
  • ~/.ssh/id_ed25519 (私钥，不要外传)
  • ~/.ssh/id_ed25519.pub (公钥，提交给平台)
  • windows：CMD / PowerShell 中输入 cd %USERPROFILE%\.ssh dir查看文件

验证连通性：

ssh -T git@github.com

看到 Hi 你的用户名! You've successfully authenticated 即成功。

第 3 步：关联本地与远程仓库

cd ~/zero-to-tech 记住：这里是ssh地址
git remote add origin git@github.com:你的用户名/zero-to-tech.git

验证：

git remote -v

第 4 步：第一次 push

先确认当前分支名：

git branch

如果是 main：

git push -u origin main

如果是 master：

git push -u origin master
如果这里有问题，切换ssh地址，以及看你的分支

日常更新流程

git add .
git commit -m "写清楚这次改了什么"
git push

服务器部署 · 从 GitHub 到公网

确认服务器上有 Git

git --version

如果 command not found，安装：

sudo apt update
sudo apt install -y git

第 1 步：把代码 clone 到服务器

cd ~
git clone git@github.com:你的用户名/zero-to-tech.git

第 2 步：看懂 Nginx 配置文件

Nginx 配置目录结构（Ubuntu 惯例）：

/etc/nginx/
├── nginx.conf (主入口)
├── sites-enabled/ (启用的站点)
└── sites-available/ (可用站点)

关键：nginx.conf 通过 include 引入其他配置，类似 HTML 的 <link>。

查看默认站点配置：

cat /etc/nginx/sites-enabled/default
核心配置行：
root /var/www/html; → Nginx 的“主目录”，所有 URL 从此拼接。

第 3 步：把 root 改成我们自己的目录

使用 vim 编辑：

sudo vim /etc/nginx/sites-enabled/default
  • 按 / 搜索 root /var
  • 按 i 进入插入模式
  • 改为 root /home/ubuntu/zero-to-tech;
  • 按 Esc，输入 :wq 保存退出

第 4 步：检查配置 + 重新加载

语法检查：

sudo nginx -t

平滑重新加载：

sudo systemctl reload nginx

第 5 步：浏览器打开 → 404？

浏览器访问 http://你的公网IP，出现 404 是预料之中的。

第 6 步：破案——权限问题

Nginx.conf 以 www-data 用户身份读取文件，不是 ubuntu。

检查 /home/ubuntu 权限：

ls -ld /home/ubuntu

如果输出最后三位是 ---，drwxr-x--- 5 ubuntu ubuntu 4096 Aug 则“其他人”无权限，修复：

sudo chmod o+x /home/ubuntu

现在刷新浏览器，页面就出现了！

本地
git status

服务器 (SSH)

这就是最朴素的“持续部署”，后续可自动化。

DNS · 端口 · 浏览器流程

  • DNS：域名 → IP 地址
  • 端口：服务的入口标识（如 80 为 HTTP）

浏览器访问网页流程

  1. 输入域名
  2. 浏览器向 DNS 查询 IP
  3. DNS 返回 IP
  4. 浏览器通过 IP 找到服务器
  5. 通过端口 80 访问
  6. 服务器返回网页
  7. 浏览器渲染显示
