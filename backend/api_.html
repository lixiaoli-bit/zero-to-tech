API · 调用笔记 从 curl 到 AI

第一个：查公网 IP

使用 ipify.org 零门槛查询，终端 + curl 即可。

curl 命令

curl 'https://api.ipify.org?format=json' ubanun可以win不行
curl https://ifconfig.me win可以

返回示例：

{ "ip": "114.86.123.45" }
这就是一次典型的 GET 请求，获取数据，干净利落。我们刚才做的这件事，就叫“调用 ipify 的 API”。

第二个：调用 DeepSeek 大模型

需要 API Key（身份钥匙）和少量余额，体验真正的 AI 接口。

准备 API Key

  • 注册 / 登录 platform.deepseek.com
  • 创建 API Key，以 sk- 开头，保存好
  • 充值少许（调用几次仅几分钱）
  • 把这个示例里面的 ${DEEPSEEK_API_KEY} 换成刚刚复制的以 sk- 开头的那段 API key。，引号留着 ubanun测试ok
  • 至于其他部分，我建议把下面这行里面的 Hello! 改为一句其他的 prompt，比如说改为 你好，请用一句话介绍你自己：

调用示例（curl）

curl https://api.deepseek.com/chat/completions \ -H "Content-Type: application/json" \ -H "Authorization: Bearer ${DEEPSEEK_API_KEY}" \ -d '{ "model": "deepseek-v4-pro", "messages": [ {"role": "system", "content": "You are a helpful assistant."}, {"role": "user", "content": "你好，请用一句话介绍你自己"} ], "thinking": {"type": "enabled"}, "reasoning_effort": "high", "stream": false }'

返回（精简后）：

{ "choices": [ { "message": { "role": "assistant", "content": "你好！我是 DeepSeek，一个由深度求索打造的 AI 助手，很高兴为你服务。" } } ] }
这就是 POST 请求，提交内容并获取回答，与 ipify 的 GET 形成对比。

API 是设计给程序用的

程序不会打开浏览器，但可以通过 API 调用服务。API 就是程序之间的“握手”入口。
  • 网页/APP 是人用的，API 是程序用的
  • 只要按规范请求，就能用上能力，无需关心内部实现
  • 一次 API 调用 = 请求 → 处理 → 响应（通常是 JSON）

GET vs POST

GET — 取数据
如 ipify 查 IP
POST — 提交数据
如 DeepSeek 对话

为什么 AI 时代到处都是 API

AI 产品、AI Agent 的本质就是不停调用各种 API：查天气、搜网页、发消息、调模型……

理解了 API，就揭开了 AI 工具神秘面纱的一大半。

回到我们的网站：前端调后端

我们的网站目前只有前端（展示 + 交互），但文字实验室的“拼音 / 情感分数”需要后端计算。解决方案：

  • 自己写一个后端 API（类似 DeepSeek 的 /chat/completions）
  • 前端把文字发给 API，后端返回 JSON（含拼音 + 情感分）
这和你刚才调 DeepSeek 是同一回事。接下来我们就要亲手写出自己的 API。

后端是什么？

  • 前端：浏览器里，负责展示与交互
  • 后端：服务器上一直运行的程序，负责计算、处理、存储
  • API：前端调用后端的入口

后端可以用很多语言写：Python、Node.js、Go、Java……我们选 Python，因为生态成熟、对初学者友好。

Python 只是选项之一，API 概念与语言无关。

这一节你应该带走什么

  • API 是程序对外的入口，按规范请求即可用
  • 一次 API 调用 = 请求 → 处理 → 响应（JSON）
  • 两个不同服务（ipify / DeepSeek）调用方式一致，都是 API
  • AI 应用天天在调 API，不神秘
  • 我们的网站即将补上后端，用 Python 写出自己的 API
